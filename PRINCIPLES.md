# User-Level Agent Context Principles

This file owns the canonical principles for AI_USE and for the user-level context systems derived from it.

## 1. Onboarding Principle

**User-level context is compact onboarding for a capable agent working with one user across projects and devices.**

Supply durable knowledge that improves judgment: the user's stable working preferences, recurring operating constraints, cross-project methods, important environment conventions, and lessons whose rediscovery carries meaningful cost.

Let models retain general intelligence, projects retain project-specific truth, code retain ordinary mechanics, and Git retain history. Context earns permanence when it materially improves future decisions. A successful route moves from a compact global entry to the narrowest relevant owner and then to direct evidence.

## 2. Singular Truth Principle

**Each durable user-level meaning has one primary local owner.**

AI_USE owns portable source material. The user's local agent context owns the personalized working state derived from that material and from later experience.

Entries and indexes route to canonical owners. Existing skills, instructions, and references should be extended when they already own the meaning. New objects earn their place when they create a genuinely distinct ownership boundary. Semantic duplication should be consolidated during synchronization and evolution.

## 3. Affirmative Direction Principle

**Shared context leads attention with the intended state, owner, condition, action, and effect.**

Express what the agent should preserve, inspect, decide, execute, or verify. Include the reason when it helps the agent generalize. Keep narrow safety constraints explicit and scoped to their owner.

Compact constructive guidance preserves model creativity while directing it toward durable user intent.

## 4. Context-First Evolution Principle

**When a durable user-level behavior or workflow changes, establish its canonical local meaning before future work depends on it.**

Experience discovered after execution enters a reconciliation step: inspect the evidence, determine whether the lesson is durable, locate its owner, and align the local context. Accepted context should describe the current working state; temporary process history remains in Git or task history.

## Experience Evolution Loop

AI_USE uses a selective feedback loop:

1. Work produces a strong trigger: a difficult reusable repair, a material user correction, or durable workflow guidance.
2. `evolve-user-agent-context` tests the candidate against a strict persistence threshold.
3. Accepted experience is classified as user-specific or broadly reusable.
4. The lesson is integrated into the narrowest canonical local owner.
5. Broadly reusable, user-independent experience may return to AI_USE after explicit user permission.

The loop preserves high-value learning while keeping global context compact.
